# 没有网关、只有手机？手把手配置 rolling-memory

> 这篇是写给**不懂代码、没有服务器、手上只有一部手机**的人。
>
> 不需要买 VPS，不需要会写 JavaScript，不需要懂什么是「网关」。全程复制粘贴，大约 20 分钟。
>
> 如果你有电脑或者 VPS，也请看第 0 节的判断表——你可能根本不用装 Termux。

---

## 0. 三十秒先判断你属于哪种

| 你手上有什么 | 该走哪条路 | 难度 | 跳转 |
|---|---|---|---|
| **只有一台安卓手机**（没有电脑、没有 VPS） | 在手机上用 Termux 跑代理 | ★★☆ | [路线 A](#路线-a只有一台安卓手机) |
| 有电脑（Windows / Mac），平常也开着 | 电脑上跑，手机填局域网地址 | ★☆☆ | [路线 B](#路线-b有电脑手机只是聊天端) |
| 有 VPS / 云服务器 | 服务器上跑，手机填公网地址 | ★☆☆ | [路线 C](#路线-c有-vps) |
| **iPhone / iPad，且只有这一台设备** | 老实说：跑不了，见说明 | — | [路线 D](#路线-diphone--ipad-怎么办) |

**先说一句最重要的**：这个模块**不需要装任何依赖**（`npm install` 都不用跑），因为它零依赖。所以「在手机上跑」这件事比你想的容易得多——装个 Node，把代码拉下来，一行命令就起来了。

---

## 1. 它到底在干什么（看懂了就不会慌）

```
你手机里的聊天 App（你照常打字、照常发消息）
        │
        ▼
http://127.0.0.1:8787/v1/chat/completions      ← 你把 App 的「接口地址」改成这个
        │
        ├─ ① 顺手记下「哪几条消息刚刚滑出了窗口」
        ├─ ② 攒够 6 条 → 后台悄悄调一次 DeepSeek，把这几条压成摘要（花你自己的 key，几分钱）
        ├─ ③ 把摘要塞进消息末尾，再原样转发给真正的对话模型
        │
        ▼
真正的模型（DeepSeek / Gemini / GPT / 任何你填的）→ 回复原样回到你屏幕
```

三件事你要知道：

1. **你的密钥、模型名、聊天内容都不会被我们经手**——代理只在你手机内部转发，请求直接打到你自己填的那家服务商。
2. **对话模型随便切**。滚动记忆存在手机里一个 JSON 文件里，跟模型无关。今天用 DeepSeek、明天换 Gemini，记忆都在。
3. **结算模型和对话模型可以不是一家**。总结用便宜的、聊天用好的是**推荐配置**，不是妥协。

> **一句话总结**：它在你的手机和模型之间插了一层「记事本」，你唯一要做的就是把 App 的接口地址指到这层上来。

## 路线 A：只有一台安卓手机

### A1. 装 Termux（**必须从 F-Droid 装**）

这一步是所有人翻车最多的地方，先看警告：

> ⚠️ **不要从 Google Play 商店装 Termux。** Play 商店那个版本 2020 年就停更了，包源过时，装 Node 会直接失败。
> 必须用 F-Droid 的版本。

步骤：

1. 手机浏览器打开 <https://f-droid.org/packages/com.termux/>
2. 点 **Download APK**（版本号 0.118.x 或更新都行）
3. 系统会提示「不允许安装未知来源应用」→ 去设置里允许当前浏览器「安装未知应用」→ 回去继续装
4. 装好后打开 Termux，**等它自己初始化 1~2 分钟**，出现这样的提示就成功了：

```
Welcome to Termux!
...
~ $
```

5. **立刻去关电池优化**（不然后面一定被系统杀掉）：
   - 小米 / Redmi：设置 → 应用设置 → 应用管理 → Termux → 省电策略 → **无限制**
   - 华为 / 荣耀：设置 → 应用 → Termux → 耗电管理 → **允许后台活动**
   - OPPO / 一加 / realme：设置 → 电池 → 应用耗电管理 → Termux → **允许完全后台行为**
   - vivo：设置 → 电池 → 后台耗电管理 → Termux → **允许后台高耗电**
   - 三星：设置 → 电池 → 后台使用限制 → 把 Termux 加入**「永不休眠的应用」**
   - 原生安卓：设置 → 应用 → Termux → 电池 → **不受限制**

### A2. 更新一下，装 Node

在 Termux 里逐条粘贴、每条按一次回车。**粘贴方法：长按屏幕 → Paste**（或者长按输入框选「粘贴」）。

```bash
pkg update -y && pkg upgrade -y
```

```bash
pkg install -y nodejs-lts git
```

装完验证一下：

```bash
node -v
```

看到 `v20.x` / `v22.x` / `v24.x` 之类的版本号就对了（只要 ≥18 都行）。如果提示 `command not found`，回上一步重装。

> 国内下载慢是正常的，Termux 的包服务器在境外。换 WiFi、或者挂个代理会快很多。

### A3. 把代码拉下来

```bash
cd ~
git clone https://github.com/zyy0463/rolling-memory.git
cd rolling-memory
```

**如果 clone 卡住或报 `Failed to connect`**（国内很常见），用下面任意一种：

```bash
# 方式一：走 GitHub 加速镜像
git clone https://ghproxy.net/https://github.com/zyy0463/rolling-memory.git
cd rolling-memory
```

```bash
# 方式二：手机浏览器直接下 zip，再用 Termux 解压
# 浏览器打开 https://github.com/zyy0463/rolling-memory/archive/refs/heads/main.zip
# 下载完在 Termux 里执行：
termux-setup-storage      # 弹权限框，点"允许"
cd ~
unzip ~/storage/downloads/rolling-memory-main.zip
mv rolling-memory-main rolling-memory
cd rolling-memory
```

> ⚠️ 代码**必须放在 `~/`（也就是 Termux 自己的家目录）**，不要放在 `/sdcard/`。安卓的外部存储有权限限制，放那儿跑不起来。

### A4. 填配置（只有 3 个必填）

```bash
cp .env.example .env
nano .env
```

现在你看到的是一个文本编辑界面。**只需要改最上面 3 行**，把 `sk-xxxx` 换成你自己的 key：

```bash
LEDGER_API_URL=https://api.deepseek.com/v1/chat/completions
LEDGER_API_KEY=sk-你自己的deepseek密钥
LEDGER_MODEL=deepseek-chat
```

这三行是「结算上游」——负责把聊过的内容压成摘要的模型。**建议就用 DeepSeek，因为它便宜**。

> **改完怎么保存退出？**（新手 90% 卡在这里）
> 按 `Ctrl + O`（字母 O，不是零）→ 按 `回车` 确认文件名 → 按 `Ctrl + X` 退出。
> Termux 没有实体键盘的话，音量上键 = Ctrl，音量下键 = 字母组合键。

**如果你用中转站**（很多人都是），再多填一行让对话走中转站：

```bash
CHAT_API_URL=https://你的中转站域名/v1/chat/completions
```

`CHAT_API_KEY` **不用填**——你的聊天 App 里本来就存着中转站的 key，代理会把它原样转发过去。

> ### ⚠️ 这里有个坑，必须看一眼
>
> `.env.example` 里原本就有这两行（是示例值，不是注释）：
>
> ```bash
> CHAT_API_URL=https://api.x.ai/v1/chat/completions
> CHAT_API_KEY=xai-xxxx
> ```
>
> **如果你不改它们**，代理会把你的对话全部转发到 x.ai，然后失败或者报密钥无效。三种处理方式，选一个：
>
> - 改成你自己的地址（中转站 / 官方接口）
> - 在前面加 `#` 注释掉
> - 直接删掉这两行（删掉后对话就走 `LEDGER_API_URL`，也就是跟结算同一家）
>
> 用 `bash scripts/termux-setup.sh` 自动生成的 `.env` 没有这个问题——它只写你填过的项。

> **一个小技巧**：把 `LEDGER_USER_LABEL` 改成你自己的名字（比如 `LEDGER_USER_LABEL=媛媛`），
> 摘要里的称呼会跟着变，读起来顺很多。

> **一句话总结**：结算那三行必须填对，填错就完全不会记忆；`CHAT_API_URL` 那两行是示例值，不改会把对话发到错的地方。

### A5. 启动

```bash
npm run proxy
```

看到这些就成功了：

```
[rolling-memory] 转发代理已启动: http://127.0.0.1:8787/v1/chat/completions
[rolling-memory]   对话上游 → https://api.deepseek.com/v1/chat/completions
[rolling-memory]   结算上游 → https://api.deepseek.com/v1/chat/completions
[rolling-memory] 把客户端的 API 地址改成上面的地址即可，密钥不用动。
```

**这个终端窗口别关**（后面 A8 教你怎么让它一直在后台活）。

想快速自测一下服务活着没有——**新开一个 Termux 会话**（从左边缘往右滑 → New session），执行：

```bash
curl http://127.0.0.1:8787
```

返回一段文字（写着"转发代理运行中"）就对了。

### A6. 把聊天 App 的地址改过来

打开你的聊天 App → 找到「API 地址 / 接口地址 / Base URL」这一栏 → 改成：

```
http://127.0.0.1:8787/v1/chat/completions
```

**密钥不要动**（还是原来那个），**模型名不要动**。

不同 App 的填法有差异，这里是最常见的几种：

| App | 填什么 | 备注 |
|---|---|---|
| **NextChat / ChatGPT-Next-Web** | `http://127.0.0.1:8787` | 它会自己补 `/v1/chat/completions` |
| **ChatBox** | `http://127.0.0.1:8787/v1` | 有些版本要完整路径，两个都试一下 |
| **LobeChat** | `http://127.0.0.1:8787/v1` | 同上 |
| **Kelivo / 各类自建客户端** | `http://127.0.0.1:8787/v1/chat/completions` | 填完整的 |
| **Cherry Studio（手机版）** | `http://127.0.0.1:8787` | 后面加 `/v1` 试试 |

**判断标准很简单**：改完发一条消息，能正常收到回复就通了。收不到就往下看排错表。

> ⚠️ **同一个手机上前提**：Termux 里的代理和聊天 App 必须装在同一台手机上，才能用 `127.0.0.1`。
> 如果 App 装在别的设备上，把 `127.0.0.1` 换成「跑代理那台设备的局域网 IP」（见路线 B）。

### A7. 确认它真的在记忆（别急着信）

聊上十几句，然后**新开一个 Termux 会话**，跑查看器：

```bash
cd ~/rolling-memory && npm run view
```

手机浏览器打开 <http://127.0.0.1:8788>，你会看到：

- **T1 近期摘要**：最近一两天聊了什么，一条一条列着
- **T2 远期梗概**：更早的骨架（故意很简略，是设计如此）
- **结算流水线**：还有几条消息在排队等着结算

**看到 T1 里出现带日期的行，就说明整条链路通了。**

还想确认花了多少钱，回到跑代理那个窗口，每次结算会打印一行：

```json
{"event":"llm_usage","mode":"rolling-settle","model":"deepseek-chat","prompt_tokens":1840,"cache_hit":0,"cache_miss":1840,"completion_tokens":310}
```

一次结算大约 2000 token 输入、几百 token 输出，DeepSeek 的价格下**一次不到一分钱**，一天几十次也就几毛钱。

### A8. 让它别被系统杀掉（保活三板斧）

安卓会把后台 App 杀掉省电——这是所有人第二天发现「记忆没了」的真正原因。三件事一起做：

**第一板斧：拿唤醒锁。** 在跑代理的那个窗口里，先按 `Ctrl + C` 停掉，然后：

```bash
termux-wake-lock
npm run proxy
```

成功的话通知栏会出现一条 Termux 的常驻通知（"wake lock held"）。

**第二板斧：用 tmux 让它脱离窗口。** 这样你切到别的 App、甚至关掉 Termux 界面，它都还在跑：

```bash
pkg install -y tmux
cd ~/rolling-memory
tmux new -d -s rm "node proxy.js"
```

查看它活着没有：

```bash
tmux ls          # 看到 rm: 1 windows 就是在跑
tmux attach -t rm   # 进去看日志（按 Ctrl+B 再按 D 退出来，别按 Ctrl+C）
```

**第三板斧：设置里的电池优化**（A1 第 5 步做过了就跳过）。小米/华为/OPPO/vivo 各家的名字不一样，关键是找到 Termux 把它设成「无限制 / 允许后台活动」。

> **验证保活成功的方法**：锁屏放 20 分钟，然后回来在 App 里发一条消息。还能正常回复 = 稳了。

### A9. 开机自动启动（可选，但强烈建议）

不然每次重启手机你都得手动敲一遍。

1. 从 F-Droid 装 **Termux:Boot**（<https://f-droid.org/packages/com.termux.boot/>），装完**先手动打开一次**它（重要，不打开脚本不会生效）
2. 回 Termux 建启动脚本：

```bash
mkdir -p ~/.termux/boot
nano ~/.termux/boot/start-rolling.sh
```

3. 粘贴下面这段（`nano` 里长按 → Paste）：

```bash
#!/data/data/com.termux/files/usr/bin/sh
termux-wake-lock
sleep 15
cd /data/data/com.termux/files/home/rolling-memory
tmux kill-session -t rm 2>/dev/null
tmux new -d -s rm "node proxy.js >> proxy.log 2>&1"
```

4. 保存退出（`Ctrl + O` → 回车 → `Ctrl + X`），然后给它执行权限：

```bash
chmod +x ~/.termux/boot/start-rolling.sh
```

5. 重启手机验证：等两三分钟，直接在 App 里发消息，能回复就说明自启成功。

`sleep 15` 是在等手机网络连上，别删。日志会写到 `~/rolling-memory/proxy.log`，出问题先看这个文件：

```bash
tail -30 ~/rolling-memory/proxy.log
```

## 路线 B：有电脑，手机只是聊天端

比 Termux 简单，也不用担心被系统杀。

**电脑上（Windows / Mac / Linux 都一样）**：

1. 装 Node（<https://nodejs.org> 下 LTS 版，一路下一步）
2. 下载仓库（或直接 `git clone https://github.com/zyy0463/rolling-memory.git`）
3. 进目录，`cp .env.example .env`，用记事本（Windows）或 `nano`（Mac/Linux）改那三行
4. 起服务：
   ```bash
   npm run proxy
   ```

**找出这台电脑的局域网 IP**：

```bash
# Windows
ipconfig        # 看"IPv4 地址"，形如 192.168.1.23
# Mac / Linux
ifconfig | grep "inet "
```

**手机上填**：

```
http://192.168.1.23:8787/v1/chat/completions
```

（把 IP 换成你上一步查到的）

**两个必须注意的点**：

1. **手机和电脑要在同一个 WiFi 下**。手机切到 4G 就用不了了。
2. **Windows 第一次启动会弹防火墙提示，必须点「允许访问」**，并且要允许「专用网络」。点了取消的话手机连不上。

> 一句话：电脑不用装什么特殊软件，就是「跑一个 node、把地址换成电脑的局域网 IP」。

## 路线 C：有 VPS

VPS 上最省事，还能多设备共用一份记忆。

```bash
# 装 Node（Ubuntu / Debian）
curl -fsSL https://deb.nodesource.com/setup_22.x | sudo -E bash -
sudo apt install -y nodejs

# 拉代码
git clone https://github.com/zyy0463/rolling-memory.git
cd rolling-memory && cp .env.example .env && nano .env   # 填那三行

# 先手动跑一次，确认能起来
npm run proxy
```

确认没问题后，用 `systemd` 让它常驻（`/etc/systemd/system/rolling-memory.service`）：

```ini
[Unit]
Description=rolling-memory proxy
After=network-online.target

[Service]
Type=simple
WorkingDirectory=/root/rolling-memory
ExecStart=/usr/bin/node proxy.js
Restart=always
RestartSec=5
EnvironmentFile=/root/rolling-memory/.env

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now rolling-memory
sudo systemctl status rolling-memory
```

手机上填 `http://你的服务器IP:8787/v1/chat/completions`。

**⚠️ 三个安全提醒，别跳过**：

1. **端口别直接暴露公网**。8787 没有鉴权，谁扫到都能用你的 key 烧钱。最省事的做法：
   - 用 `ufw` 只放行你自己的 IP：`sudo ufw allow from 你的手机出口IP to any port 8787`
   - 或者用 Tailscale（手机上装一个、服务器上装一个，填 Tailscale 内网 IP），完全不暴露公网
   - 或者套 Nginx + HTTPS + BasicAuth 反代
2. **`viewer.js` 千万不要暴露公网**（8788 端口的查看器能直接改你的记忆，而且没有密码）。
3. 服务器安全组/防火墙都要放行对应端口，只在面板里开是不够的。

## 路线 D：iPhone / iPad 怎么办

**坏消息**：iOS 不允许在设备上跑 Node 进程，所以「手机装个终端跑代理」这条路在 iPhone 上**没有可靠方案**。iSH 之类的模拟器能装 Node，但会被系统随时挂起，锁屏几分钟就断，不适合长期跑。

**能给的三条替代路**：

1. **借一台常开的设备**（旧安卓手机、旧笔记本、树莓派、VPS），按路线 B / C 跑代理，iPhone 上填那台设备的地址。
2. **借家里的路由器/群晖/NAS**——如果它会跑 Docker，起一个 Node 容器就行。
3. **退一步：不用代理，手动搬摘要**。iOS 上有很多客户端支持「自定义系统提示」。你可以定期让模型自己总结一下最近聊了什么，存进系统提示里。体验远不如自动的，但至少能接上。

## 排错表：按症状找

### 代理起不来

| 报错 | 原因 | 怎么办 |
|---|---|---|
| `command not found: node` | Node 没装好 / 装到了错的 Termux 版本 | 用 F-Droid 版重装，再 `pkg install nodejs-lts` |
| `LEDGER_API_URL / LEDGER_API_KEY / LEDGER_MODEL 未配置` | `.env` 没建 / 没填 / 在别的目录启动了 | `cd ~/rolling-memory` 再启动；`cat .env` 检查有没有内容 |
| `Cannot find module './index'` | 没在仓库目录里启动 | `cd ~/rolling-memory` |
| `EADDRINUSE` | 8787 端口被占了（可能已经起了一个） | `pkill -f proxy.js` 然后重来；或改 `PROXY_PORT=8790` |
| 一切正常但一发消息就断 | Termux 被系统杀了 | 回去做 A8 三板斧 |

### App 连不上

| 症状 | 原因 | 怎么办 |
|---|---|---|
| App 报 `Failed to fetch` / 连接被拒 | 代理没在跑，或地址写错 | 先 `curl http://127.0.0.1:8787` 自测；确认端口是 8787 |
| 报 `cleartext HTTP traffic not permitted` | 安卓禁止 App 用明文 http | 换一个允许 http 的客户端（NextChat / ChatBox 一般没问题），或者给代理套一层 https |
| 手机连不上电脑上的代理 | 不在同一 WiFi / 防火墙拦了 | 手机浏览器访问 `http://电脑IP:8787`，打不开就是网络问题 |
| 返回 404 | 地址少了或多了一段 `/v1/chat/completions` | 按 A6 的表逐个试 |
| 返回 401 | 密钥没带过去 | 检查 App 里的密钥还填着没有；中转站的话确认 key 没过期 |
| 返回 400 且提示 `response_format` | 中转站不支持 json 模式 | 换一家中转站，或者把结算上游换成 DeepSeek 官方直连 |
| 报错里出现 `api.x.ai` / `xai` / 模型不存在 | `.env` 里的 `CHAT_API_URL` 还是示例值 | 改掉、注释掉或删掉那两行（见 A4 的警告） |

### 记忆不出来

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 聊了很久 T1 还是空的 | 攒的消息还不够一批（默认 6 条滑出才结算一次） | 多聊几句；或把 `LEDGER_BUFFER_COUNT` 改成 `3` |
| 查看器里待结算缓冲一直是 0 | App 每次只发最后一条消息（不带历史） | 这个模块依赖「请求里带完整窗口」，客户端设置里找「发送上下文/历史消息数」，调大 |
| 有结算日志但摘要没变 | 结算模型返回的内容解析失败 | 看 `proxy.log` 里有没有 `failed_batches`；换一个归纳能力更好的模型 |
| 换模型之后记忆断了 | 换模型时 App **新开了会话** | 必须在**同一个会话**里切模型（详见下方 FAQ） |
| 早上起来全没了 | 被系统杀了 / 手机重启了 | 做 A8 + A9 |

## 常见问题

**Q：会不会很费电、很占内存？**
平时几乎不占——它只是转发请求，CPU 基本空转。只有攒够一批消息时才调一次模型，几秒钟就结束。内存常驻大约 60~80MB。真正费电的是「一直亮着网」，建议充电时用、或者拿备用机跑。

**Q：换对话模型（DeepSeek ↔ Gemini）会不会断？**
不会，**只要你在同一个会话里切**。滚动记忆存在手机本地，跟模型无关，换模型后新模型读到的还是那份摘要。但如果你换模型时**新开了一个对话**，就会出问题：新会话的历史是空的，代理会以为「窗口突然变了」，要么把旧窗口整批重记一遍，要么把旧尾巴丢掉。**所以：切模型，别新开会话。**

**Q：能同时开两个会话吗（比如一个聊感情、一个写代码）？**
**不建议**。目前只有一份记忆文件，没有按会话隔离，两条线会串在一起，还会重复记。要用就一次只开一个。

**Q：我的 key 安全吗？**
安全。密钥只在你的手机/电脑上，代理是原样转发给服务商的，不经过任何第三方服务器。但**别把 8787 端口暴露到公网**——那样别人能白用你的 key。

**Q：一天大概花多少钱？**
按 DeepSeek 的价格，一次结算不到一分钱，一天几十次大约几毛钱。聊天本身的钱另算（那是你自己选的模型）。想省钱就让结算固定走 DeepSeek。

**Q：T2 里更早的事怎么查不到了？**
设计如此。T2 是「噪声沉降池」，故意把远期内容压成极短骨架、7 天后直接丢。**需要长期记住的事请写进专门的记忆库**，别指望 T2。

**Q：它能不能代替记忆库？**
不能。滚动记忆管的是「**紧接着的对话**别断片」（近两天），长期事实、偏好、重要事件要靠检索式记忆库。两者互补。

## 一页速查（安卓纯手机，复制即用）

```bash
# 1. 装环境（F-Droid 装好 Termux 之后）

termux-wake-lock
```

## 还是搞不定？

按这个顺序自查，90% 的问题能自己解决：

1. `curl http://127.0.0.1:8787` 有没有返回文字？（代理活着吗）
2. `cat .env` 那三行填了吗？key 有没有多余空格？
3. `tail -30 ~/rolling-memory/proxy.log` 最后几行报什么错？
4. `npm run view` 里有没有 T1 内容？（记忆链路通不通）
5. 电池优化关了吗、唤醒锁拿了吗？（是不是被系统杀了）

把第 3 步的日志贴出来提问，比说「它不工作」有用一百倍。
